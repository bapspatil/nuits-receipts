Paths are relative to the app's root. With `APP_BASE_PATH` set (for example `/app`), every path starts with that prefix. Every page needs sign-in. Where a page takes `month`, the value is `YYYY-MM` and defaults to the current month (UTC).

## Main navigation

Every page has the same five links, in this order. On a wide screen (880 pixels or more) they are in the header. On a narrow screen they are in a tab bar fixed to the bottom of the screen, each with an icon. The link for the page you are on is marked. The tab bar hides while you type in a field, so it does not cover the keyboard.

| Link | Path | Badge | Marked on |
| --- | --- | --- | --- |
| Home | `/` | | Home |
| Review | `/review` | Number of documents and Unknown sender emails waiting | Review, and a document that needs review |
| Receipts | `/receipts` | | Receipts, Invoices, Add, and a document that does not need review |
| Bank | `/payments` | Number of payments missing a receipt | Bank and the bank statement import |
| Settings | `/settings` | | Settings |

In Access mode the header also shows **Sign out**, which goes to `/cdn-cgi/access/logout`. On a phone, **Sign out** is at the top of **Settings**.

Every page ends with a short notice: check every figure, it is not tax or accounting advice, there is no warranty, and the app is not affiliated with Cloudflare or with any bank.

**Receipts** has two views at the top: **Receipts** (`/receipts`) and **Invoices** (`/invoices`). **Invoices** appears once `INVOICES_ADDRESS` is set or at least one sales invoice exists; `/invoices` works either way.

Month screens (Home, Bank, Invoices, and Receipts with `month`) use the month as their title, between links to its neighbours: ‹ Aug  September 2026  Oct ›.

### Settings sections

In page order. Each section is a fold, closed by default, with a one-line summary next to its title. A link to `/settings#<anchor>` opens that section, and a save returns with its section open.

| Section | Anchor | Summary | Contains |
| --- | --- | --- | --- |
| Business | `#setup-business` | Business name and parts, such as "Example Studio Oy, 4 parts" | App name, business names, parts of the business, default part, payment terms, new account currency. |
| Email | `#setup-email` | Receipt address, or "Off" | Receipt address, invoice address, forward copy address. The confirmation tick shows only once you change an address. After saving a changed address, the "Now update Cloudflare Email Routing" checklist. |
| Senders | `#senders` | "2 allowed" | Allowed senders with **Remove**, an address box with **Add**, and **Ignored** senders with **Stop ignoring**. |
| Bank accounts | `#accounts` | Number of accounts | Accounts with bank and currency, **Rename**, and the account ID under **More**. **Add account** (Name, Bank, Currency, **Create**). Notes at `#imports` and `#transfers` point to **Bank**, where those moved. |
| Vendor rules | `#rules` | Number of rules | One row per rule, such as "Sample Cloud → Hosting, infra · 5" (the priority shows only when it is not 0). Open a row to edit it (Seller contains, Part, Kind, Also mentions, Bank name, Priority) with **Save** or **Delete**. **Add rule**. |
| Export | `#setup-accountant` | Accountant name | Accountant, export file name, note under the month download. |
| OneDrive | `#onedrive` | Account, "Not connected" or "Not set up" | Shown only when `MS_CLIENT_ID` is set. **Connect**, the account, the folder (**Change folder**, **Use folder**), **Disconnect** and **Redirect URI** (for Microsoft Entra). |
| Advanced | `#advanced` | | **Review & matching** thresholds, **Integrations** (the source code link), **Set at deploy** (read-only deploy values) and **Change history** (the last 20 setting changes). |
| About | `#about` | | The full no-warranty notice, the data line "Runs in your own Cloudflare account. Nuits doesn't receive or store your data.", the Apache-2.0 licence link, and the trademark and not-affiliated lines. |

Each field is a label and an input; its help is the field's tooltip. Each section has one **Save**, and **Reset** shows next to a value set in the app. See [Configuration](/reference/configuration/).

## Form actions

Each form posts to one of these paths and then redirects (303).

| Path | Does | Goes back to |
| --- | --- | --- |
| `/accounts`, `/accounts/<id>` | Add or rename a bank account. | `/settings#accounts` |
| `/transfers`, `/transfers/<id>/undo` | Pair or undo an own-account transfer. | Bank for the month the money left, `#transfers` |
| `/rules` | Add a vendor rule. | The receipt it was made from, else `/settings#rules` |
| `/rules/<id>`, `/rules/<id>/delete` | Change or delete a vendor rule. Unknown IDs return 404; a rule with the same seller and context text returns 409. | `/settings#rules` |

## Sign-in and OneDrive routes

| Path | Purpose |
| --- | --- |
| `/settings/onedrive/connect` | Starts the Microsoft sign-in. |
| `/settings/onedrive/callback` | Microsoft returns here after sign-in. This is the redirect URI to register in Microsoft Entra, prefixed with the app's origin and `APP_BASE_PATH`. |

## Responses without sign-in

| Mode | Response |
| --- | --- |
| Password (HTTP Basic) | 401 with a `Basic` challenge whose realm is `APP_NAME`. Sign-in also fails over plain `http` except on `localhost`, `127.0.0.1` and `[::1]`. |
| Cloudflare Access | 403 "Sign in through Cloudflare Access to use this app." |

Every form post must carry an `Origin` header equal to the app's origin, or it is refused with 403. Unknown paths return 404.
