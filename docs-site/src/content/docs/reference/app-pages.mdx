Paths are relative to the app's root. With `APP_BASE_PATH` set (for example `/app`), every path starts with that prefix. Every page needs sign-in. Where a page takes `month`, the value is `YYYY-MM` and defaults to the current month (UTC).

## Main navigation

Every page has the same four links, in this order, each with an icon. On a wide screen (880 pixels or more) they are in a sidebar. On a narrow screen they are in a tab bar fixed to the bottom of the screen. The link for the page you are on is marked.

| Link | Path | Badge | Marked on |
| --- | --- | --- | --- |
| Home | `/` | | Home |
| Receipts | `/receipts` | Number of items in Receipts To do | Receipts To do and All, Invoices, Add, and a document |
| Bank | `/payments` | Number of payments missing a receipt | Bank and the bank statement import |
| Settings | `/settings` | | Settings |

In Access mode the header also shows **Sign out**, which goes to `/cdn-cgi/access/logout`. On a phone, **Sign out** is at the top of **Settings**.

Every page ends with a short notice: check every figure, it is not tax or accounting advice, there is no warranty, and the app is not affiliated with Cloudflare or with any bank.

**Receipts** and **Bank** each have a **To do | All** switch at the top, with the count of each. To do is the default: what needs you, open items first. All is everything, to browse. In Receipts All, a second switch picks **Receipts** or **Invoices**, and the month arrows show.

Month screens (Home, Bank, Invoices, and Receipts All with `month`) use the month as their title, between links to its neighbours: ‹ Aug  September 2026  Oct ›.

### Settings sections

In page order. Each section is a fold, closed by default, with a one-line summary next to its title. A link to `/settings#<anchor>` opens that section. The page has one **Save** at the bottom for every section.

| Section | Anchor | Summary | Contains |
| --- | --- | --- | --- |
| Business | `#business` | Business name, and the number of parts once there are two | App name, business names, payment terms, new account currency, the parts of the business (**Add a part**), and **Vendor rules** (`#rules`). |
| Email | `#email` | Receipt address, or "Off", and the number of allowed senders | Receipt address, invoice address, forward copy address, and **Email senders** (`#senders`): allowed senders with **Remove**, an address box with **Add**, ignored senders with **Stop ignoring**, and **Mail we didn't keep** (`#mail`), the latest 50 emails that were not read, with **Allow**. |
| Bank | `#bank` | Number of accounts | Bank accounts with bank and currency, and **Add account**. |
| Sending | `#sending` | Accountant name | Accountant, export file name, the note under the month download, and **OneDrive** when `MS_CLIENT_ID` is set (**Connect**, the folder, and **Disconnect**, which asks first). |
| Advanced | `#advanced` | | The review and matching thresholds, the source code link, read-only deploy values, the change history, and **About** (`#about`): the no-warranty notice, the data line, the licence and the trademark lines. |

Each field is a label and an input; its help is the field's tooltip. **Reset** shows next to a value set in the app. See [Configuration](/reference/configuration/).

## Select several

Receipts To do and All, Invoices, Bank and the sender lists in **Settings > Email** have a tick box on every row, on every screen size. Ticking a row shows a bar with the count ("3 selected"), **Clear** and the list's actions. An action that cannot be undone asks first.

Shift-click ticks a range, `x` ticks the focused row and Esc clears. **Select all N** ticks every row under the list's filter and month, across pages; above 500 it reads **Select the first 500**, in the list's order. These need JavaScript; without it, the boxes and the bar work for the rows on the page.

| List | Actions |
| --- | --- |
| Receipts To do | **Approve** (receipts missing a required fact are skipped), **Discard** |
| Receipts All | **Discard**, **Read again**, **Move to invoices** or **Move to receipts**. Under Discarded, only **Restore**. |
| Invoices | **Mark paid**, **Discard**, **Read again** |
| Bank | **Match** (only payments with an exact likely receipt), **Not a purchase**, **Needs a receipt**, **Unmatch** |
| Settings > Email senders | **Remove** for allowed senders, **Stop ignoring** for ignored ones |

The banner says how many changed and how many were skipped, and offers **Undo**. The rows that changed leave the list, and the next open ones move up. Read again and Move call the reading model in chunks and have no Undo. See [Limits](/reference/limits/#use) for the caps.

## Form actions

Each form posts to one of these paths and then redirects (303).

| Path | Does | Goes back to |
| --- | --- | --- |
| `/accounts`, `/accounts/<id>` | Add or rename a bank account. | `/settings#accounts` |
| `/transfers`, `/transfers/<id>/undo` | Pair or undo an own-account transfer. | Bank for the month the money left, `#transfers` |
| `/receipts/bulk`, `/payments/bulk`, `/senders/bulk` | Run one [bulk action](#select-several) on the ticked rows, or with `all=1` on every row the list's filter matches. A post without its list state is refused with 400. | The list it came from, at the next open row, with a result banner and **Undo** |
| `/rules` | Add a vendor rule. | The receipt it was made from, else `/settings#rules` |
| `/rules/<id>`, `/rules/<id>/delete` | Change or delete a vendor rule. Unknown IDs return 404; a rule with the same seller and context text returns 409. | `/settings#rules` |

## Sign-in and OneDrive routes

| Path | Purpose |
| --- | --- |
| `/settings/onedrive/connect` | Starts the Microsoft sign-in. |
| `/settings/onedrive/callback` | Microsoft returns here after sign-in. This is the redirect URI to register in Microsoft Entra, prefixed with the app's origin and `APP_BASE_PATH`. |

## Responses without sign-in

| Mode | Response |
| --- | --- |
| Password (HTTP Basic) | 401 with a `Basic` challenge whose realm is `APP_NAME`. Sign-in also fails over plain `http` except on `localhost`, `127.0.0.1` and `[::1]`. |
| Cloudflare Access | 403 "Sign in through Cloudflare Access to use this app." |

Every form post must carry an `Origin` header equal to the app's origin, or it is refused with 403. Unknown paths return 404.
